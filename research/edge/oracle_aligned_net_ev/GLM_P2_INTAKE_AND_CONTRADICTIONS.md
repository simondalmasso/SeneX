**Issue:** https://github.com/simondalmasso/SeneX/issues/205. **All code and data here are research-only documentation fixtures, not authenticated original venue data.** No HTTP/WS, signing, authentication, wallet, order or trade pathway exists. A local raw SHA and journal chain verify relative file integrity but do not prove timestamps, external immutability, authenticated source, oracle settlement, or any prospectively valid T0/T1.

## Provider / original attachment contract

`OriginalOfflineCustody.record(raw: bytes, source_class, parser_version, received_wall_ms, received_monotonic_ns, market_id, condition_id, asset_id, connection_id)` requires an independently supplied original-byte buffer. Raw bytes are stored under O_EXCL as `raw_<sequence>_<SHA256>.bin`, fsynced, hashed, linked to a canonical JSONL chain and checked on every reopen. Torn journals, changed/missing blobs, unexpected files and sequence gaps stop rather than self-repair. The *derived* `normalized` view is stored separately in the journal, tied to original byte digest, parser version and source identity. `source_admissible=false`, `eligible=false`, `label_authority=UNVERIFIED` **always**. SDK-normalized data is labeled `SDK_DERIVED_NOT_ORIGINAL_WIRE`. Capturing monotonic nanoseconds is only for local ordering; it is never compared directly with epoch millisecond event timestamps. Local wall-clock accuracy is not independently attested.

Contracts are deliberately disjoint: Gamma metadata with `id/conditionId/clobTokenIds/outcomes` (unverified rule and token version); CLOB REST `market/asset_id/timestamp/hash/min_order_size/tick_size/asks/bids`; legacy `crypto_prices_twap_sixty` `btc/usd/window_s=60/full_accuracy_value` E18; PolyBolt wire `{v,channel,seq,ts,snapshot?,dropped?,payload}` on `price.crypto.twap`, decimal string `full_accuracy_value` (no E18); SDK-normalized `prices.crypto.twap` event `subscribe|update` for `btcusd` and `windowSeconds=60`. These examples are NOT signed source observations. PolyBolt source sequences are scoped to connection + channel; the first update without that connection's preceding snapshot is rejected. The legacy RTDS snapshot is never a forward event. PolyBolt RTDS migration https://docs.polymarket.com/migrate/rtds-to-polybolt. No implicit CTF/V2 version proof, market-specific 300s rule/tie authority or actual fee source is inferred from Gamma's undocumented synthetic keys: those gates remain blocked.

## Economic semantics and non-conclusions

`classify_buy` enforces source condition/token/hash, valid timestamp and age, per-observation `min_order_size`, Decimal `tick_size` price grid, strictly positive noncrossed depth and enough asks under price cap for the specified shares. `classify_sell` requires explicit positive inventory and bid depth; no naked sale. Every valid result is `QUOTE_ONLY_NONMONETIZABLE` with `fill_proven=false`. Sequential YES/NO quotes yield `NON_ATOMIC_PAIR`, never an atomic fill. No fill probability can be estimated from a deterministic depth walk.

`paper_buy` calculates *conditional hypothetical* fee, premium and hold-to-resolution payoff using a **caller-supplied**, not universal, rate; `fee=shares×rate×p×(1−p)` with local HALF_UP rounding explicitly unverified versus venue. `fee/premium = rate×(1−p)` before costs, e.g. rate .07: 6.93% at .01; 3.5% at .50; .07% at .99. No fee or slippage is charged to a nonmatched hypothetical action. No round-trip can be computed absent separately evidenced sell costs, inventory and fills. Rebate/ maker incentives are not automatically credited. Neither `paper_buy(matched=True)` nor a valid quote is a verified fill, so no realized PnL is exposed.
